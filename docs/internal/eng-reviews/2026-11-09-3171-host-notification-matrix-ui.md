# feat(notifications): add simplified host notification preferences UI (#3171)

Pull request: #3810
Issue: #3171
Review basis: focused frontend UI diff against `acceptance`
Result: provides a simple per-notification channel selector; persistence and delivery enforcement are handled in the follow-up PR.

## Scope

- Add seven host-facing notification categories and 87 event options.
- Show only the notification name and three delivery choices: In-app, Email and SMS.
- Add a quick action to turn off or re-enable email for all events.
- Remove internal metadata such as actions, priority and recipients from the user-facing screen and UI catalog.
- Add English, Dutch, German and Spanish labels.

## Findings and decisions

| Severity | Area | Finding | Decision |
|---|---|---|---|
| P1 | Persistence | The UI component needs the follow-up preference API integration before selections persist across sessions. | This PR adds the reusable UI; the next PR wires loading and saving. |
| P2 | Accessibility | Channel checkboxes have event-and-channel-specific accessible labels; category navigation uses keyboard-operable buttons. | Keep native checkbox controls and accessible labels. |
| P2 | Responsiveness | The four-column notification table is horizontally scrollable on narrow screens. | Keep the event names readable and allow the three channel columns to scroll when required. |

## Validation

- Added component tests for categories, all three channels, bulk email opt-out and load-error behavior.
- Confirmed 87 unique event keys are generated by the frontend catalog.
- Tests have not been run locally; CI must validate the PR.
