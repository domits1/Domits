## What changed

```
document  (one row per document, host-scoped)              document_version  (immutable, one row per file)
┌──────────────────────────────────────────┐   document_id  ┌───────────────────────────────────────────┐
│ id, host_id, title, category,            │ ◀───────────── │ id, document_id, host_id, version_number, │
│ status 'active', visibility 'internal',  │                │ storage_key, file_name, mime_type,        │
│ review_status, issue/expiration_date,    │ ──────────────▶│ file_size, checksum, uploaded_by          │
│ archived_at, deleted_at                  │ current_       │ CHECK version_number >= 1, file_size > 0  │
└──────────────────────────────────────────┘ version_id     │ UNIQUE (document_id, version_number)      │
                                                            └───────────────────────────────────────────┘
Both arrows are logical: no foreign keys. document_relationship and document_activity follow in their own migration.
```

- Migration `20261124_document.{js,sql}` and `_rollback.sql` for `test` (suffix `_test`) and `main`. The four `CREATE TABLE` blocks are byte-identical to the ones on `3870-document-tables` (#4046). Smoke blocks: one document, versions 1 and 2, a repeated version 1 with `ON CONFLICT DO NOTHING`, the two default checks and `versions_should_be_two`. Four negative blocks, one per CHECK and schema. The zero-rows check lists the six smoke ids used.
- `Document.js` and `Document_Version.js`: identical to #4046 (checked by blob hash). Registered in `Tables.js` after `Property_Owner_Property`.
- `schema.psql`: both tables for `main` and `test`, after each schema's `property_owner_property` block.
- `dsql_document_runbook.md`: purpose, DSQL rules, 13 blocks with expected counts, rollback, status, and a note that the other two tables follow separately.
- `documentEntity.test.js` (208 lines): data, the shared `describeOrmConsistency`, `itEndsEveryTransactionInRollback` and `itCountsOnlySmokeRowsInFinalCheck` from `support/ormConsistencyTestHelpers.js`, and the checks specific to this migration. It defines no SQL helper of its own.
