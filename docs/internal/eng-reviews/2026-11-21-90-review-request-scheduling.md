## Four passes

1. Architecture: reviewed scheduling ownership/operations authorization, controller routing, conditional claims, revalidation before delivery, completion races, email enrichment/transport and login return navigation. Existing service/repository boundaries are reused. Delivery is an at-most-once attempt; uncertain outcomes require reconciliation. Deployment ownership is incomplete in the tree (findings 2 and 3).
2. Code quality: inspected validation, publication visibility, moderation search/pagination, history ownership/editability, HTML escaping, HTTPS URL checks, failure codes and UI error/retry behavior. The concrete release-path defect is finding 1. Prior records were evidence to recheck, not proof that their proposed fixes landed.
3. Tests: repository SQL construction and mocked service/UI tests cover many paths, but mocks conceal the missing import in the actual release method. Current test execution results appear below. Passing tests cannot establish runtime IAM, scheduler existence or real HTML delivery.
4. Performance: selection is bounded to fifty, processing sequential, enrichment uses three parallel reads, public pages are bounded and recent reviews use a stable date/id cursor. Schedule settings add two reads around a claim. No production SQL plans, runtime latency or remaining-time budget were measured; a timeout can retain SENDING claims by design.
