## Four passes

- Architecture: layering is kept. The new data access (ReviewInvitationRepository) sits in data/, the template builder in business/, injected into the notifier. One extra dependency per send: a database read for title, city and first READY web image variant. The shared email Lambda contract gains an optional `htmlBody`; its source lives outside the deploy pipeline (finding 4).
- Code quality: user and property data is HTML-escaped; image and logo URLs must be HTTPS without credentials; S3 keys are encoded per path segment; missing details fall back to neutral text. Pre-send failures are not distinguished from uncertain delivery (finding 1).
- Tests: builder (branding, escaping, missing data, unsafe URLs, invalid frontend URL), repository SQL shape against real TypeORM metadata, notifier payload and per-property image, URL default/override. Missing: service behaviour when `getDetails` rejects or the frontend URL is invalid.
- Performance: three parallel queries per send, at most fifty sends per batch, sequential. The image query is LIMIT 1 on an indexed property filter. No concern at current volume.

## What already exists

Reuses the claim/delivery flow, GetUserInfo lookup, EmailNotificationService transport, Property / Property_Location / Property_Image(_Variant) models and the public S3 URL convention used by profile photos and company logos. No new package.

## Failure modes

| Path / failure | Test | Handling | Visible |
|---|---|---|---|
| getDetails database error | Yes | FAILED, never retried | Log, code PROPERTY_DETAILS_UNAVAILABLE |
| FRONTEND_URL not HTTPS | Yes | Batch stops before claiming; nothing consumed | Scheduler invocation error, code INVALID_FRONTEND_URL |
| Property without image/title/city | Yes | Neutral fallback, no image | Guest sees generic text |
| Deployed email Lambda ignores htmlBody | No | Plain text sent | Nobody notices |
| Hostile title/name/city | Yes | Escaped | Rendered as text |

Before the fix, the first two rows had handling but no service test and only an UNKNOWN log line as symptom.
