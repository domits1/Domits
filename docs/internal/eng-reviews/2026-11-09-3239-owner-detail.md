# feat(property-owners): show an owner on a detail page with archive and restore

Pull request: (to be opened)

Reviewed commit: uncommitted changes on top of 972941147
Result: no blocking findings

Covers the new page `hostowners/pages/HostOwnerDetail.js` at `owners/:id`, the owner name in `OwnersTable.js` becoming a link to it, the route in `mainDashboardHost.js`, the `hostOwners.detail` texts in the four language files and the styles in `HostOwners.scss`. `ownerContent.js` holds the language lookup that `HostOwners.js` had, so both pages share it. `OwnersTable.js` now exports `OwnerProperties`, `statusClassName` and `percentFormatter` so the detail page uses them instead of copying them. `ConfirmDialog` is imported from `hosttasks/` and not changed.

Mutation checks on the detail page tests. Each change below was made on purpose, and at least one test failed for each: a 409 not recognised, a 409 that still marks the owner archived, Cancel that archives, Archive without the question, Restore that sends the whole owner, Restore through the archive route, buttons that never disable, an archive result that is not shown, and a page without `key={id}` that keeps the first owner's state.
