## Fix 4: close success toasts automatically and keep errors open

Reviewed: uncommitted changes on top of 4758876f2

Covers one rule in `styles/toast-notifications.scss`.

Root cause: the rule `.Toastify__progress-bar { display: none !important; }` stopped the progress-bar animation. react-toastify 11 has no separate timer; it closes a toast when the progress bar's CSS animation ends (`animationend`). An element with `display: none` never runs its animation, so no toast in the app closed on its own, whatever `autoClose` was set to.

Fix: the rule is removed, so every toast closes after the container's `autoClose={5000}` in `App.js`. The bar stays invisible because `hideProgressBar` already gives its wrapper `data-hidden="true"`, which the library styles as `opacity: 0`. A new rule, `.Toastify__toast--error .Toastify__progress-bar, .Toastify__toast--warning .Toastify__progress-bar { animation: none; }`, keeps error and warning toasts open until they are clicked. Its two-class selector wins over the library's one-class `.Toastify__progress-bar--animated`. Keeping errors and warnings open relies on react-toastify's internal close mechanism (the progress-bar `animationend`), not on its documented API. Re-check it after every react-toastify upgrade.

The change is global: it is one rule in the app-wide toast stylesheet, so it applies to every toast in the app, not only the onboarding Photos step. No `toast.*` call and no `ToastContainer` prop changed. No Jest test is possible: jsdom does not run CSS animations, and Jest stubs stylesheets. The behaviour was verified manually in the browser on the onboarding Photos step: success and info toasts close after about 5 seconds, error toasts stay until clicked.
